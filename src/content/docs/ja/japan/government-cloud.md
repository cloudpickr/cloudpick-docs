## 概要

ガバメントクラウド（Government Cloud）は、日本のデジタル庁（デジタル庁）が政府機関と地方公共団体（自治体）が共通して利用できるよう整備するクラウド基盤です。2021年に施行された「地方公共団体情報システムの標準化に関する法律」を根拠とし、「政府情報システムにおけるクラウドサービスの適切な利用に関する基本方針」が採択した**クラウド・バイ・デフォルト原則**の中核的な実行手段です。

政府各府省の情報システムだけでなく、全国1,700余りの自治体が運営する基幹業務システム（住民記録・税務・福祉など20業務）も、この共通基盤へ移行することが目標とされています。すなわちガバメントクラウドは、特定のデータセンターや単一のサービスではなく、デジタル庁が審査を経て「利用可能」と指定したクラウドサービス事業者（CSP）の一覧と、その上でシステムを構築・運用するための共通機能・ガイドラインの総体です。

:::note
ガバメントクラウドは、各国の行政・公共機関クラウド転換政策と目的は類似していますが、事業者選定を単一の調達庁ではなくデジタル庁が毎年公募・審査する方式で運用しており、自治体システム標準化という別個の立法と強く結びついている点が異なります。
:::

ガバメントクラウド事業者の選定は2020〜2021年、AWS・Google Cloud・Microsoft Azure・OCIの4大ハイパースケーラーを最初の対象として始まり、以降は毎年度の公募を経て対象サービスの範囲が拡大してきました。2023年11月にはさくらインターネットが日本国内事業者として初めて条件付きで採択され、2026年3月に正式認定を受けたことで、現在の5事業者体制が整いました。

## 登録事業者現況 (2026年8月時点)

2026年度ガバメントクラウド整備対象サービスに指定された事業者は次の5社です。

| 事業者 | 登録状況 | 備考 |
| --- | --- | --- |
| Amazon Web Services (AWS) | 正式登録 | 制度初期（2021〜2022年）から登録事業者として参加 |
| Microsoft Azure | 正式登録 | 制度初期から登録事業者として参加 |
| Google Cloud | 正式登録 | 制度初期から登録事業者として参加 |
| Oracle Cloud Infrastructure (OCI) | 正式登録 | 制度初期から登録事業者として参加 |
| さくらインターネット（さくらのクラウド） | **正式登録**（2026年3月27日） | 2023年11月に条件付き採択 → 2025年度末までに約305件の技術要件充足を条件に、2026年3月に正式認定 |

:::note
さくらインターネットは、日本国内（自国）事業者としては唯一ガバメントクラウドに登録された事業者です。2023年11月に「2025年度末までに全技術要件を満たす」ことを条件に採択された後、統制・セキュリティ認証・オブジェクトストレージなど残る要件を順次解消し、2026年3月に正式認定に至りました。
:::

## ISMAPとの関係 — 二重ゲート構造

ガバメントクラウドと[ISMAP](../ismap/)は別個の制度ですが、直接結びついています。

- **ISMAP登録は前提条件であり十分条件ではありません。** ガバメントクラウド事業者に選定されるには、対象サービスがまずISMAPクラウドサービスリストに登録されている必要がありますが、ISMAP登録だけで自動的にガバメントクラウド事業者になるわけではありません。
- ISMAP登録後もデジタル庁が別途実施する**技術要件審査**(性能・可用性・セキュリティ・ガバナンスなど数百項目)を通過する必要があり、さくらインターネットの事例のように条件付き採択後、数年かけて要件を満たすケースもあります。
- 結果として日本の公共クラウド調達は**①ISMAP登録 → ②ガバメントクラウド事業者審査**という二重ゲートを通過しなければならない構造であり、自治体システム移行が拡大するほどこのゲートの実務的な影響力も大きくなっています。
- 逆に、ガバメントクラウド事業者として認定された後もISMAP登録自体を喪失すると（更新審査で不合格になるなど）ガバメントクラウドの資格も併せて維持しにくい構造であるため、両制度は実質的に一連の連続したコンプライアンスサイクルとして捉えるべきです。

## 事業者選定方式 — 年単位の公募・審査

ガバメントクラウド事業者は一度限りで確定するのではなく、デジタル庁が年度単位で公募・審査を繰り返す構造です。

1. **年度別公募**: デジタル庁が該当年度（例: 2026年度）の「ガバメントクラウド整備のためのクラウドサービス」調達公告を出します。
2. **技術要件審査**: 応募事業者は性能・可用性・セキュリティ・ガバナンス・監査対応など数百項目の技術要件充足の可否について審査を受けます。ISMAP登録はこの段階の前提条件です。
3. **条件付き採択オプション**: さくらインターネットの事例のように、審査時点で一部要件を満たしていなくても「特定期限までに満たす」ことを条件に条件付き採択される場合があります。
4. **正式認定・更新**: 条件充足が確認されれば正式認定され、以降の年度公募でも引き続き資格を維持するには再審査に対応する必要があります。

この方式は毎年新規事業者が参入する余地を残す一方、既存の登録事業者にも毎回の要件変化への対応という負担を課します。

## 自治体システム標準化の現況

「地方公共団体情報システムの標準化に関する法律」は、住民記録・税務・福祉など**20の基幹業務システム**を国が定めた標準仕様に合わせて全国の自治体が共通化し、これをガバメントクラウドへ移行するよう規定しています。

| 時点 | 内容 |
| --- | --- |
| 2021年 | 標準化法施行、原則移行期限を2025年度末（2026年3月）に設定 |
| 2024年12月24日 | 基本方針を再改定 — 移行が困難なシステムは「特定移行支援システム」に分類し、2030年度末まで国が移行経費を含めて支援 |
| 2026年1月末時点 | 全体移行完了率**38.4%** |
| 2025年12月末時点 | 対象34,592システムのうち**8,956システム（25.9%）**が特定移行支援システムに分類される見込み — 対象自治体1,788団体のうち935団体（52.3%）がこれに該当 |
| 2026年3月末時点（公式確定値） | 特定移行支援システムとして確定分類されたシステムは、対象34,366システムのうち**10,013システム（29.1%）** — 2025年12月の見込み値（25.9%）を上回って確定 |

:::caution
原則期限である2025年度末（2026年3月末）は過ぎましたが、移行難易度・開発ベンダーのリソース不足などの理由から相当数のシステムが2026年度以降に持ち越されました。国は移行経費を含め総額約7,000億円規模の予算を確保し、支援期限を2030年度末まで延長しています。個別自治体・システムの最新の移行スケジュールは[デジタル庁](https://www.digital.go.jp/)および総務省の発表で確認する必要があります。
:::

## 実務上の示唆

- **単一リストではない二重審査**: ISMAP登録の有無だけではガバメントクラウド適合性を判断できません。公共調達を目標とする組織は、ISMAPリストとは別にデジタル庁のガバメントクラウド事業者リストも併せて確認する必要があります。
- **国内リージョン・国内事業者の選択肢**: さくらインターネットは、データレジデンシーや「国産クラウド」要件に敏感な自治体・府省庁を対象とした代替経路として位置づけられつつあります。ただしハイパースケーラー4社が依然としてサービス範囲・機能の成熟度で優位にあり、ワークロードの性質によって選択肢は変わります。
- **移行スケジュールの遅延を前提とした設計**: 標準化移行率が2026年1月時点で38.4%にとどまり、支援期限が2030年度まで延長された以上、今後数年間はレガシーシステムとガバメントクラウド基盤上のシステムが共存する過渡期が続くと見込まれます。この期間の連携・移行支援需要をアーキテクチャや事業計画に反映する必要があります。
- **年単位の再審査リスク**: ガバメントクラウド事業者資格は毎年度の公募・審査を通じて更新される構造であるため、特定事業者の登録が恒久的に固定されたものとは前提しない方が安全です。長期契約を設計する際は、登録状況の変更可能性に備えた条項を検討する必要があります。
- **外資系・グローバル企業の視点**: 日本の公共部門にSaaS・プラットフォームを提供しようとするグローバル企業であれば、自社サービスがハイパースケーラーのガバメントクラウド登録リージョン（東京・大阪など）上で稼働するかをまず確認し、自治体向け事業の場合は特定移行支援システムのスケジュール（最長2030年度）まで見据えた長期ロードマップを立てることが安全です。
